## Быстрый старт на Windows

Принять приглашение GitHub в am1cs/aic-bazaar. Использовать Git for Windows и
Node.js LTS. Открыть PowerShell в рабочей папке и выполнить:

```powershell
git clone https://github.com/am1cs/aic-bazaar.git
cd aic-bazaar
git fetch origin
git switch --track origin/codex/part-2-web
```

Если ветка ещё не опубликована, вместо последней команды:
`git switch -c codex/part-2-web origin/main`.
Открыть эту папку как проект в Codex. Rust, Solana CLI и WSL для части 2 не нужны.
Авторизоваться в GitHub для push через обычный Git Credential Manager;
не вставлять пароль, токен или seed-фразы в чат.

## Что сделать

1. Прочитать AGENTS.md, INTEGRATION.md, shared/api.ts и статус части 1.
2. Создать web/ на React + TypeScript + Vite + Tailwind. Хранить зависимости и
   lockfile только внутри web/. Подключить Phantom через Solana Wallet Adapter.
3. Сделать четыре экрана: главная, создание, сделка с этапами, спор/арбитраж.
   Просмотр по URL работает без кошелька, действия доступны по реальному адресу.
4. Формы, лимиты UTF-8, расчёт выплат в целых lamports, SHA-256 локального файла,
   проверка HTTPS-ссылок, сроки, статусы и доступные действия следуют INTEGRATION.md.
5. Вызывать исключительно общий BazaarClient. До готовности SDK допустим
   отдельный экран разработки с фикстурами и видимой надписью «UI preview — no
   blockchain transactions». Финансовое состояние не хранить в localStorage.
6. Подключить настоящий SDK после первого PR части 1. Реализовать ожидание подписи,
   отправку, подтверждение, ошибки, Explorer links и обновление аккаунта из сети.
7. Проверить полный успешный сценарий и спор с тремя отдельными кошельками,
   обновление страницы, неправильный кошелёк, отмену подписи и недоступный RPC.
8. Развернуть на Vercel. Рабочая директория сборки — web/. Проверить прямое открытие
   URL сделки и отсутствие обязательного логина для просмотра.
9. Подготовить собственные демонстрационные concept/draft/final материалы;
   провести два коротких UX-прогона, записать реальные наблюдения в docs/usability.md.
10. Подготовить product demo до 3 минут и сценарий в docs/demo.md. В видео показывать
    реальные транзакции Devnet. Человек публикует видео в своём согласованном аккаунте.

## Ранние передачи первому участнику

- Первая: интерфейс четырёх экранов по общему API, без привязки к структуре Anchor.
- Вторая: подключённый кошелёк и SDK create/accept/read, публичный preview сайта.
- Третья: все реальные действия, результаты пользовательских проверок и demo.
- Каждая передача — небольшой PR + обновлённый docs/status/part-2.md.

Не редактировать contracts/, sdk/ или deployment/devnet.json. Несовпадения SDK
описывать первому участнику с ожидаемыми и фактическими данными.

## Готово, когда

Сайт доступен публично, читает реальные аккаунты без кошелька, завершает успешную
сделку и спор через SDK, показывает ошибки без ложных выплат, сохраняет состояние
после reload и имеет проверенную видеодемонстрацию. Тестовые фикстуры не выдаются
за работающий escrow и не используются в production transaction path.
