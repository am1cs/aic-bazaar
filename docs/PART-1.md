# Часть 1 — контракт, SDK и Devnet

Владелец: @am1cs (macOS). Ветка: `codex/part-1-contract-sdk`.
Объём: примерно половина общей работы, с основной ответственностью за деньги.

## Что сделать

1. Прочитать `AGENTS.md`, `INTEGRATION.md`, `shared/api.ts` и статус части 2.
2. Создать Anchor-программу в `contracts/`. Сначала получить рабочую сборку и
   deploy в Devnet; использовать Solana Playground, если локального toolchain нет.
   Экспортировать исходники, тесты и настоящий сгенерированный IDL в репозиторий.
3. Реализовать семь инструкций: create_deal, accept_deal, submit_milestone,
   approve_milestone, open_dispute, resolve_dispute, cancel_unaccepted.
4. Реализовать SDK в `sdk/`, точно соответствующий `BazaarClient` из shared/api.ts.
   SDK отвечает за PDA, сериализацию, IDL, построение и отправку транзакций,
   подтверждение, преобразование аккаунтов и ошибок в общий интерфейс.
5. Проверить escrow, права подписантов, все выплаты/возвраты, гонки сдачи и оплаты,
   повторные вызовы, максимальные размеры полей и сохранение rent.
6. Заполнить `deployment/devnet.json`: публичные Program ID, arbiter address,
   demo deal addresses, RPC URL без секретных ключей, идентификатор проверенного
   git commit. Никогда не класть сюда keypair.
7. Подготовить две проверенные Devnet-сделки: завершённую и разрешённую после спора.
   Приложить ссылки на реальные транзакции в docs/technical.md.
8. Подготовить техническую часть README и текст pitch в docs/pitch.md; факты о
   команде и спросе не выдумывать. Запись pitch распределить с человеком.

Друг строит UI по shared/api.ts и не должен ждать всех инструкций сразу.
Не реализовывать web/ и не менять его package-lock.json.

## Обязательные тесты

- Три выплаты и возврат залога, включая бюджеты с остатком при округлении.
- Отмена до принятия; невозможность принять отменённую сделку.
- Все три исхода спора после первого оплаченного этапа; уже оплаченные средства
  не изымаются, будущий бюджет всегда возвращается заказчику.
- Чужие подписанты и подменённые получатели отклоняются.
- Двойные выплаты, действия в неправильном состоянии и после закрытия отклоняются.
- Нельзя оплатить несданный, следующий или изменившийся этап.
- Вторая сдача допустима, третья запрещена; оплаченные материалы неизменяемы.
- Во время спора сдачи и обычные выплаты запрещены.
- Выплаты + возвраты + остаток обязательств равны внесённым средствам, отдельно
  от rent, комиссий и любых посторонних переводов на PDA.
- Транзакции с максимальными полями сериализуются и помещаются в сетевые лимиты.

## Готово, когда

Контракт реально развёрнут в Devnet; SDK вызывает его из браузера; тесты проходят;
IDL соответствует развернутому коду; есть две проверяемые сделки и README.
Если deployment недоступен, назвать это блокером, не подменять его mock-режимом.
